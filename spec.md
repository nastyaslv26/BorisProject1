# Спецификация

## Назначение

Node.js-приложение отдаёт сохранённый интерфейс сайта из `index.html` и предоставляет фиксированный API меню. Страница доступна по `GET /` и `GET /index.html`; файл интерфейса сохраняется без замены.

## API

- `GET /api/menu` возвращает JSON с тремя позициями: `cinnamon-capibara` («Коричная капибара»), `vanilla-croissant` («Ванильный круассан») и `chocolate-croissant` («Шоколадный круассан»).
- `POST /api/selection` принимает JSON вида `{"id":"vanilla-croissant"}`. Допустимы только идентификаторы из меню. Валидный запрос получает локальное подтверждение с названием позиции; неверный JSON или неизвестный идентификатор отклоняется.
- `POST /api/reset` возвращает JSON-сообщение о сбросе выбора.
- `GET /api/status` возвращает JSON с `ok: true` и временем сервера в ISO 8601.
- Любые остальные сочетания пути и HTTP-метода получают явный HTTP 404.

## Технические ограничения

- Используются только встроенные модули `node:http`, `node:fs` и `node:path`.
- Запуск слушает `0.0.0.0`; порт берётся из `PORT`, локальное значение по умолчанию — `3000`.
- Сборка — проверка синтаксиса `server.js` командой Node.js, без сборщиков и внешних пакетов.
- Проект не имеет внешних зависимостей, базы данных, Docker, Volume, Variables и внешних интеграций.
- Выбор не сохраняется ни в памяти сервера, ни в файлах или SQLite. `POST /api/reset` только подтверждает сброс и не меняет серверное состояние.
- Amvera использует Node.js 18, `npm run build`, `npm run start` и контейнерный порт `3000` из `amvera.yaml`.

## Границы

API не реализует записи на прогулки, расписание, учёт ФИО или постоянное состояние. Существующий интерфейс отдаётся как есть; его прежние запросы к API не входят в контракт этой версии. Не добавлять функции, хранилища или интеграции сверх указанных маршрутов.
