# План ручной проверки

1. Выполнить `npm install`, `npm run build`, затем `npm start`; убедиться, что сервер слушает `0.0.0.0:3000`.
2. Открыть страницу в двух браузерах или в обычном и приватном окне. Проверить пять слотов: 09:00, 11:00, 13:00, 15:00, 17:00.
3. В первом окне записаться в свободный слот. Убедиться, что во втором окне не позднее чем через четыре секунды слот показан занятым с указанным ФИО.
4. Одновременно отправить две записи на один слот или повторить запись через `POST /api/bookings`; один запрос должен получить HTTP 201, второй — HTTP 409.
5. Проверить `GET /api/state`: дата соответствует текущему дню, занятые слоты содержат ФИО, остальные доступны. После перезапуска сервера записи сохраняются в SQLite.
6. Проверить пустое/слишком длинное ФИО и неизвестный слот: API должен ответить HTTP 400. Проверить `GET /api/status` и HTTP 404 для неизвестного маршрута.
7. Для деплоя подключить репозиторий в Amvera и проверить страницу и API после запуска. Для постоянного хранения файла SQLite между пересозданиями контейнера настроить постоянный путь `DATABASE_PATH` согласно возможностям тарифа.
