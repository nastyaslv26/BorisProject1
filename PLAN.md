# План проверки

1. Выполнить `npm run build`.
2. Запустить сервер с временным путём к SQLite-базе, чтобы тестовые записи не попадали в рабочие данные.
3. Открыть `/` и проверить, что страница показывает ровно пять окон: 09:00, 11:00, 13:00, 15:00 и 17:00.
4. Проверить `GET /api/state`: ровно пять фиксированных окон и занятость из SQLite; проверить загрузку последней отметки кормления (ФИО и время) или `null`, если отметок нет.
5. Отправить валидную запись через `POST /api/bookings`, проверить её появление в `/api/state`, перезапустить сервер с той же базой и убедиться, что запись сохранилась.
6. Повторить запись в занятое окно и проверить HTTP 409; проверить неизвестное окно, пустое/слишком длинное ФИО и некорректный JSON на HTTP 400.
7. Проверить `GET /api/status`, неизвестный маршрут и неподдерживаемый метод.
8. Отправить отметку кормления через `POST /api/feedings`, проверить отказ для пустого после обрезки ФИО, отображение последнего имени/времени в карточке и сохранение после перезапуска сервера.
